## Current

### L-UI-001  Automate the UI only after REST, MCP, cloning and XHR capture are exhausted
**Kind:** DECISION · **Proven:** 2026-09-29 · **Evidence:** Capability maps of the September log and the per-operation verdict reference · **Supersedes:** L-UI-025, L-UI-026
Order of attempts for an operation that looks UI-only: (1) the REST route on the right host with the right plane header, plus the probe toolkit (bogus twin, empty POST, Content-Type); (2) a managed MCP tool; (3) a clone through a v3 export/import package; (4) capture the UI's own XHR for that click and replay it headless; only then (5) drive the UI with Playwright, or hand one precise click to a human. Many September "UI-only" steps fell at steps 1-4 (service and connector selection, MCP OAuth clients, CAI publish, ingestion deploy, glossary writes, catalog-source create, profile runs, mapping authoring as IMF JSON). Still UI in these sources on 2026-09-29: MDM model publish and deploy, match-merge job creation, CLAIRE classification accept, steward assignment, CAI API activate, CDQ rule logic and console scorecards, CDQ dictionary "Convert to API", catalog-source definition delete (REST only purges), MCP tool-connection import, publishing API-created advanced taskflows, and discovering unknown property names (for example a pushdown setting).

### L-UI-002  Capture the UI's own API calls to replace a UI step with REST
**Kind:** PROCESS · **Proven:** 2026-09-29 · **Evidence:** The MCP OAuth-client and service-selection routes proven headless on 2026-09-28 came from this approach; an unredacted login capture found in a harness log (2026-09-29)
Log in once with a headless browser, open the page, record every XHR and fetch to `*.informaticacloud.com` (method, status, URL, request body with any password field redacted in the capture hook itself, the head of the response), filter the noise (telemetry, translations, icons, i18n, notification polls) and click the control. The captured request is the headless route: replay it with the helper's session. This found the MCP OAuth-client route and the runtime-environment selections route. Never paste captured cookies or Authorization headers into chat; keep only method, URL, body shape and status. The capture also records the identity-service login request, whose body carries the username and password in clear: redact login and password bodies at capture time (not afterwards), keep capture logs out of shared folders and transcripts, and rotate the password if an unredacted log was shared (L-METHOD-087).

### L-UI-003  Log in to the IDMC console with Playwright
**Kind:** RECIPE · **Proven:** 2026-09-28 · **Evidence:** Logins scripted from a Windows workstation and from server containers between July and September
Open `https://<domain>.informaticacloud.com/identity-service/home`, wait for `input#username` (or `input[name=username]`), fill username and password from environment variables, and submit with `button:has-text("Log In"):not(:has-text("Single"))` (which skips the SSO button) or Enter. Some login pages are two-step (username, Log In, then password, Log In), so wait for the password field before filling it. After login the browser lands on `https://<pod>.<domain>.informaticacloud.com/cloudshell/showProducts`, and SSO carries to every service host. Scripted login works only for a user without MFA.

### L-UI-004  Stop at the first rejected login, and never auto-login from a probe on a shared account
**Kind:** LAW · **Proven:** 2026-09-28 · **Evidence:** UI harnesses ran through a migration without causing a lockout
After submitting, if the page is still on the identity service and its text matches `locked|not valid|invalid`, exit with "LOGIN REJECTED - not retrying": UI logins count toward the same lockout as REST logins. A probe that only measures rendering reuses a warm storage state read-only, never logs in by itself, aborts if it is bounced to the login page, and does not write the state back, so it cannot clobber a session that other runs depend on.

### L-UI-005  Reuse a saved storage state inside the session window; refresh it before each batch
**Kind:** GOTCHA · **Proven:** 2026-09-28 · **Evidence:** Empty grids with a reused stale state; batches ran cleanly after a login refresh · **Supersedes:** L-UI-024
Save `storage_state` after one login and reuse it (every login counts toward the lockout), but the console session lives about 30 minutes (JWT iat to exp about 1800 s): a stale state makes deep links redirect and grids render empty. Refresh the state with one explicit login command before each batch, and log in fresh when a run will outlast the window.

### L-UI-006  Storage-state files and browser profiles are credentials
**Kind:** SECURITY · **Proven:** 2026-09-22 · **Evidence:** State files and a profile cache were flagged and sequestered in a KB inventory
A Playwright storage state holds the console's cookies, including session JWTs (one held 46 cookies), and a persistent browser profile cache can hold live session cookies too. Treat both as secrets: keep them out of repositories, shared folders and the script's own directory, give them 0600, sequester or delete stale ones (Playwright regenerates a profile), and never paste their contents.

### L-UI-007  IDMC single-page-app quirks that break naive automation
**Kind:** GOTCHA · **Proven:** 2026-07-09 · **Evidence:** Each quirk reproduced and worked around by the July UI drivers
Deep links such as `/explore/<id>` render empty on a cold load: navigate (Explore, All Projects, click) to hydrate. Heavy authenticated pages may never fire `load`: use `wait_until="commit"` or `"domcontentloaded"` plus `wait_for_url` and a specific element wait. A service-switcher modal intercepts clicks until closed (`button[aria-label=Close]` or Escape). Apps are embedded in frames: search every frame (`page.frames`) for controls and pick the right one by URL (the CAI shell frame's URL contains `bpmui-cai-app`). Grid rows are `role=row`, with a kebab menu that appears only on hover; react-select options match `[class*='-option']` (a `role=option` belongs to a background grid, and Escape closes the modal). Nested SPAs (the CAI designer under `/aiUI/`, Data Marketplace) rendered blank headless with a saved state: use a fresh login and a headed browser under `xvfb-run`.

### L-UI-008  Driving the mapping designer: CodeMirror, long queries, stuck spinners, target re-derive
**Kind:** RECIPE · **Proven:** 2026-08-19 · **Evidence:** Mappings stayed Valid; a target went from 16 to 21 mapped fields; runs produced engine-changed rows
Set expression or query text by calling the CodeMirror instance (`cm.setValue(<text>)` then `cm.save()`), then click the dialog's dynamically enabled OK; never press Escape before the commit (it discards the edit); call `scrollIntoView` on fields below the fold. Typing hundreds of lines with `press_sequentially` exceeds its 60 s default: use `delay=1, timeout=300000` and poll for OK to enable. A very large custom query (about 6 KB or more) can hang the field-derive spinner on a new mapping (the URL never becomes a GUID and Save is a no-op): list `DTEMPLATE` objects over v3 REST, open the auto-persisted `MappingN` by GUID and continue; capture the GUID from the URL right after the first save. After adding upstream ports, rename a create-at-runtime target (set the value with the native input setter and answer Continue) to force the designer to re-derive the target fields.

### L-UI-009  UI authoring is slow and must be serial
**Kind:** PERF · **Proven:** 2026-08-19 · **Evidence:** Per-object durations across 16 authored objects
Authoring one CDI mapping plus its task through the designer with a Playwright subagent took about 30-75 minutes, rising with query size; parallel authoring sessions collided on shared storage-state files and on the same scratch target. Author serially, one object per browser session, and prefer a headless import path whenever one exists.

### L-UI-010  UI receipts: the verbatim confirmation plus a REST read-back
**Kind:** PROCESS · **Proven:** 2026-07-26 · **Evidence:** First receipt captured, with the engine count growing from 1 to 23 on read-back
For a UI-only operation a screenshot proves a click, not a commit. Record the console's confirmation text verbatim (it also identifies which dialog ran), the UI path, the REST call it substitutes for, and a REST read that verifies the change; for agent services the receipt was "Changes successful. The selected components are enabled for the runtime environment, and all unselected components are disabled for the runtime environment.", verified with `GET /api/v2/agent/details/<agentId>`. Receipts are captured by a user or by automation, never invented; capture failure strings too, because failure toasts and silent no-ops look alike in a screenshot. A confirmation is not completion: engines sat in DEPLOYING for 20-45 minutes or more while packages downloaded, so re-read before concluding that the action failed.

### L-UI-011  Behind a transparent enterprise proxy, IDMC SPAs render blank under automation
**Kind:** WALL · **Status:** disputed · **Proven:** 2026-09-20 · **Evidence:** A DOM body of 2 nodes and 0 text across 5 configurations; about 130-160 MB of egress spent proving it · **Supersedes:** L-UI-027
From a laptop behind a transparent TLS proxy with CGNAT addressing, login and the launchpad rendered but every heavy IDMC micro-frontend (Data Profiling, Administrator) painted nothing, because its bootstrap requests failed (a worker script 404, a CORS block on the `hdm` host, a DNS failure on another service host, a 503 from a UI service). Headless, headful, `--disable-web-security` and a real Edge channel on a warm session all failed: a fresh automation profile does not get the proxy's enterprise network treatment, whatever the browser engine. Chromium flags that disable Private/Local Network Access checks (for proxies that resolve vendor hosts to 100.64/10 addresses) had helped earlier but were not sufficient. Run UI automation from a host outside the proxy (a cloud VM), or hand the click to the user's own browser. Disputed 2026-10-06 by L-UI-031: with the Local Network Access checks also disabled, the catalog, MCC and the mapping designer worked headless from such a proxy.

### L-UI-012  Detect a blank or logged-out page mechanically
**Kind:** GOTCHA · **Proven:** 2026-09-20 · **Evidence:** Blank DOM measured on 5 configurations; identical screenshots before a login fix
Measure what the SPA painted instead of trusting a screenshot: in each frame count DOM elements, visible text length, buttons and inputs (`document.body.getElementsByTagName('*').length`, `innerText.length`); a body of 2 nodes and 0 text is blank. Byte-identical screenshot sizes across different pages mean you are photographing the login page (for example with a tool that ignores HTTP Basic credentials in the browser).

### L-UI-013  Run Playwright on a server in the official container
**Kind:** RECIPE · **Proven:** 2026-09-28 · **Evidence:** Screenshot rigs and UI walks ran from server containers; a browser suite ran on a VM without Node for the first time
Use `mcr.microsoft.com/playwright/python:<ver>-jammy` with `pip install playwright==<same ver>` inside it and `-e PLAYWRIGHT_BROWSERS_PATH=/ms-playwright`, run it with `--network host`, and mount an output folder for screenshots, page text and XHR logs; the Node image (`mcr.microsoft.com/playwright:<ver>-jammy`) runs JS suites on hosts without Node. Launch Chromium with `--no-sandbox` in the container. Map vhost names with `--add-host` so the browser can resolve them, and build a throwaway image from a temporary copy to preview changes safely.

### L-UI-014  Screenshots and page text as evidence, one per step
**Kind:** PROCESS · **Proven:** 2026-09-24 · **Evidence:** Six capabilities verified by walks with per-step screenshots
For each capability that must be shown in the IDMC UI, write acceptance criteria, walk it headless from a server, and save a full-page screenshot plus the page text per step (`page.screenshot(full_page=True)`, `page.inner_text("body")`), with the login state kept in a file refreshed by a login command. Pass free-text inputs (for example chat prompts) through a JSON file, because shell wrappers split arguments on spaces. Save objects that the UI flags as "unsaved changes" before a demo.

### L-UI-015  Drive CLAIRE GPT with a browser harness
**Kind:** RECIPE · **Proven:** 2026-09-29 · **Evidence:** About 70 recorded runs
A harness on a server logs in, submits prompts from a JSON file, waits while the page shows busy text and auto-clicks "proceed". Match the busy text including its trailing dots (for example "Analyzing concepts...") or the harness exits early; allow 50-110 s per answer; start a new conversation per prompt; avoid `@` in prompts (it opens the mention picker and the prompt is never sent); refresh the saved login before a batch. Answers are nondeterministic, so pin the good conversations before a demo.

### L-UI-019  SaaS setup steps with no API: a frontdoor session plus Playwright, verified by API
**Kind:** RECIPE · **Proven:** 2026-09-26 · **Evidence:** Stream status ACTIVE and ruleset PUBLISHED on read-back
For CRM setup steps that have no REST API (for example activating a data stream or renaming an identity-resolution ruleset in Salesforce), open an authenticated session with `sf org open --url-only` (a frontdoor URL), drive the page with Playwright, then verify through SOQL or the Metadata API.

### L-UI-020  Verify dashboards in a real browser, and log in through the form
**Kind:** GOTCHA · **Proven:** 2026-10-02 · **Evidence:** Byte-identical screenshots before the fix; browser errors that a 200 API check had missed; an API check green while a UI gap existed, and 176 of 176 per-channel UI stories passed after the fix (2026-10-01/02)
Passing HTTP Basic credentials to Playwright does not log in to some BI tools (the screenshots then capture the login page): fill the login form. API-only dashboard checks can pass while the panel throws in the browser (for example a target missing `url_options`), and re-issuing a simplified query can return 0 rows while the panel is fine: verify against the exact feed a panel reads and with a real-browser render. Drive end-to-end stories through every channel's real UI (web, mobile web, self-service terminals, staff consoles) before trusting downstream IDMC counts: an API-driven check passed while one channel had no screen for a step at all, so records that should have fed the pipeline were never created from it. Keep slow verification reads (warehouse or database queries of 20-80 s) out of timed UI flows: screens with idle resets (45 s, 3 min) time out the next click, so verify at the end of the story.

### L-UI-021  Playwright can author real IDMC design objects
**Kind:** OVERTURNED · **Proven:** 2026-08-19 · **Evidence:** Session-log rows written; 16 of 16 objects authored and run · **Supersedes:** L-UI-022, L-UI-023
The belief that the first mapping of a new source/target pair must be hand-authored fell when a Playwright session authored a PostgreSQL-to-warehouse mapping in the designer and its session log showed rows written (2026-07-07); by 2026-08-19 sixteen mappings with their tasks had been authored through the designer by automation, and profiles were created through the UI on 2026-09-03. Once such a seed exists, variants can be cloned headlessly; by 2026-09-29 mappings could also be built as IMF JSON and imported with no UI at all.

### L-UI-028  A settle rule for a CLAIRE GPT browser harness that neither exits early nor waits out the timeout
**Kind:** RECIPE · **Proven:** 2026-09-30 · **Evidence:** About 60 multi-step runs; a data prompt cut at 76 s with no table passed in 116 s with the table after adding U+2026 (8/8 set)
Record the page text length before sending and read only what comes after it, or an earlier reply's completion marker ends the wait at once. Treat the reply as busy while its last ~60 non-space characters contain the spinner text, which is letter-spaced in the page text ('L o a d i n g . . .'), so strip whitespace before matching. Never use a bare '...' as a busy marker (a refinement of L-UI-015): the input placeholder 'Ask CLAIRE...' always contains it, so every step waits out the full timeout. Treat the reply as done on markers ('let me know', 'would you like', 'shall I proceed', 'Cards (<n>)') or on text that stays unchanged and spinner-free for 150 s. After clicking an allowed button or chip, press Enter (L-MCP-079), and send a scripted follow-up only when you mean it: a harness that sends the next follow-up whenever no allowed button is visible posts it as a new prompt. The status line 'Checking available connections…' ends in U+2026 (a single ellipsis character), not three dots: add U+2026 to the busy patterns, because without it the harness treated the status as a finished answer and cut a data prompt before its table arrived (re-check earlier 'no table' failures for this cause).

### L-UI-029  Pin, unpin, rename and delete CLAIRE GPT conversations headless
**Kind:** RECIPE · **Proven:** 2026-09-30 · **Evidence:** 9 pins with renames, one swap, the Pinned tab's titles read back
Hover the list item that holds `span[data-testid=chat-nav-link]`; the row then shows `button[data-testid=chat-pin-button]` ('Pin Conversation'), `chat-edit-button` (rename: fill the inline input and press Enter) and `chat-delete-button`, and on the Pinned tab `chat-unpin-button` ('Unpin Conversation'). A rename can silently not stick, so list the Pinned tab's titles afterwards and fix any stray row. On a shared account, touch only conversations you created, matched by exact title or conversation id. Reopened conversations collapse their cards behind 'Cards (<n>)' and drop query results, so a pinned fallback shows the answer text but not its data preview.

### L-UI-030  A CLAIRE GPT harness needs a publish guard: stop at Publish/Accept prompts, and audit the org afterwards
**Kind:** RECIPE · **Proven:** 2026-10-01 · **Evidence:** A run without the guard published one rule specification; about 150 guarded runs created nothing beyond one dictionary (L-MCP-097), checked with v3 objects by update time
Give the harness an explicit allow-list of buttons (for example only 'Yes, proceed with the plan' and 'Proceed without testing') and a deny-list it never clicks (Publish Rules, Accept, save, delete). Before sending any scripted follow-up, check the newest reply: if 'Publish Rules / Don't Publish Rules', an 'Accept rule' chip or a save offer is visible, stop the scenario or click 'Don't Publish Rules' plus Enter, because free text at that prompt can be taken as consent (L-MCP-096). Auto-answer only harmless clarifications ('The Table'). After each batch, list `GET /public/core/v3/objects` for rule specifications, dictionaries, mappings, tasks and mapplets updated since the batch began, and record what was created.

### L-UI-031  Headless Chromium with the Private and Local Network Access checks off drove the catalog, MCC and the mapping designer behind a proxy again
**Kind:** WORKAROUND · **Proven:** 2026-10-06 · **Evidence:** screenshots and captured write requests from all three consoles in one day; a blank auth loop without the flags
From a laptop behind the kind of transparent proxy L-UI-011 describes, Playwright's bundled Chromium, headless, launched with `--no-sandbox --disable-features=BlockInsecurePrivateNetworkRequests,PrivateNetworkAccessSendPreflights,PrivateNetworkAccessRespectPreflightResults,LocalNetworkAccessChecks,LocalNetworkAccessChecksWarn`, a saved storage state and at most one scripted login rendered and finished work in Metadata Command Center (catalog source pages, lineage configuration), Data Governance and Catalog (asset pages, the lineage tab, new-asset forms with multi-step pickers) and the Data Integration mapping designer. Without the flags the console looped on authentication and stayed blank. Data Profiling and Administrator were not retested, so L-UI-011 is disputed: try this flag set before moving UI work to a cloud host.

### L-UI-032  Driving catalog pickers with Playwright: exact button names, Finish on the last step, check the radio input itself
**Kind:** RECIPE · **Proven:** 2026-10-06 · **Evidence:** a substring match reset the wizard twice; exact names, Finish and the forced radio check completed the form and created the asset
In the catalog's multi-step pickers (for example a rule occurrence's Primary Data Element: catalog source > data set > data element) the stepper tabs are buttons too, so `get_by_role('button', name='Select')` matches the tab 'Select System or Catalog Source' and sends the wizard back to step 1: pass `exact=True`. The last step's button is 'Finish'; a parameter-mapping step ends with 'OK'. Search inside a picker by clicking its box and typing, then click the row by exact text. Radio buttons such as 'Pick an existing rule' draw the input over the label, so a label click times out ('input intercepts pointer events'): call `check(force=True)` on `input[type=radio][value=...]`. Use the form once to capture its write request, then replay that over REST (L-CDGC-161).

### L-UI-033  The intelligent structure model editor spins forever in headless Chromium: wait for openStructureData instead
**Kind:** GOTCHA · **Proven:** 2026-10-06 · **Evidence:** spinner on every model tried; openStructureData 200 each time
In headless Chromium the model editor keeps showing a spinner, for models made in the UI and over REST alike. A 200 response from the service's `openStructureData` request is the real 'loaded' signal: wait on that response, not on the spinner.

### L-UI-034  In the mapping designer, copy a selection of transformations to clone a whole flow
**Kind:** RECIPE · **Proven:** 2026-10-06 · **Evidence:** a second flow built by copy, then repointed; both flows ran in one task
Selecting a flow's transformations and copying them duplicates the flow with its links, edited field precisions and field mappings; rename the copies, repoint the source settings, and order the flows in Flow Run Order. It is the quickest way to build a second, similar flow in the same mapping.

### L-UI-035  Small mapping-designer traps: date fields rename themselves, descriptions lose symbols, pasted copies get a 1
**Kind:** GOTCHA · **Proven:** 2026-10-07 · **Evidence:** each seen while building a three-flow mapping in a headless browser
In the New Field dialog, choosing a date/time type resets the name to 'NewField': rename it afterwards (double-click the field and type). The mapping description strips `<`, `>` and apostrophes, so write those in words. Pasted copies of transformations get '1' appended to each name. Arrange All puts each flow on its own row.

### L-UI-036  Sweep the Mapping Designer headless for Invalid badges the API does not report: deep links per object kind, the Validation panel, an exact 'Log In' click
**Kind:** RECIPE · **Proven:** 2026-10-26 · **Evidence:** Sweep of 2 mappings, 2 mapping tasks and 2 linear taskflows read each badge; one Invalid mapping found and fixed; one scripted login per batch (2026-10-26)
Open each object at `https://<pod>.<domain>.informaticacloud.com/diUI/products/integrationDesign/main/<kind>/<frsId>/read`, or `/edit` to change it. The kinds are `mapping`, `mct` (mapping task) and `linearTaskflow`; a folder opens at `.../main/explore/<folderId>`. Use a saved storage state (L-UI-005). Wait 35-45 s for the canvas, then read the Valid or Invalid badge in the page header and the 'Validation (<n>)' panel. Each item's detail arrow shows the full message, for example a rule specification whose definition changed. Log in on the identity-service page by filling `#username` and `#password` and clicking the button named exactly 'Log In' (exact match). A substring match also hits the SSO button. Stop on the first failed login, because every attempt counts toward the user's lockout (L-AUTH-095). A designer-only Invalid state (L-DQ-113, a stale rule-spec copy) is found only this way.

### L-UI-037  Enabling org source control and entering Git credentials are UI-only: automate the two screens with Playwright, and expect a 'Configure' button
**Kind:** WALL · **Proven:** 2026-10-02 · **Evidence:** Read-only form dumps, then save attempts 2026-10-02/03: one fill timed out after 64 retries on a disabled field; dialog text 'Enter the Git credentials ... User Name Personal Access Token Configure Cancel'
No REST endpoint configures source control for an org or stores a user's Git credentials. The org screen is Administrator > Settings > Source Control > Edit (Enable Source Control, Enable Project Level Source Control, Allow Push to Git Repository, Platform, Repository Type, Global Git Repository URL, Global Git Branch Name, OAuth, Runtime Environment); the per-user screen is user menu > Settings > Source Control Access (Git user name plus a personal access token with full repository control, e.g. GitLab scope `api`). Traps seen live: the Edit control is an icon button (`aria-label="Edit"`), not a text button; after Save a modal 'Git Repository Configuration Credentials' asks for User Name and Personal Access Token and its primary button is 'Configure', not OK or Save; a Playwright `fill` on a still-disabled field retries silently every 500 ms until its 30 s timeout ('element is not enabled'), so wait for the field to be enabled or for the dialog. Build a read-only walk first (open, dump the fields, Cancel), then a save run that logs every non-GET and every >=400 XHR. Users see no source-control columns or actions until they enter their own credentials.

## Superseded / overturned (kept so nobody re-learns them)

### L-UI-022  Playwright is a screenshot tool for IDMC, not an automation path, overturned 2026-08-19
**Was believed:** 2026-07-10 · **Overturned by:** L-UI-021
A July review counted 102 Playwright-on-IDMC scripts, found none documenting a successful mutating action, and rated every browser-dependent capability as a human click. Designer authoring by automation (08-19) and UI-created profiles (09-03) contradicted it; the lasting part is that UI automation is slow, fragile and a last resort.

### L-UI-023  The first mapping of a new source/target pair can only be authored by hand, overturned 2026-07-07
**Was believed:** to 2026-07-06 · **Overturned by:** L-UI-021
Clone authoring could not change a mapping's connector types, so the first mapping for each new source/target pair was believed to need a human in the designer. A Playwright session authored one on 2026-07-07, and IMF JSON import removed the UI step entirely by 2026-09-29.

### L-UI-024  Log in fresh in each script, overturned 2026-09-03
**Was believed:** 2026-07-06 to 2026-07-08 · **Overturned by:** L-UI-005
Because the console session is short, early runbooks logged in at the start of every script. Login volume counts toward the account lockout, so the later rule is to reuse one saved state within the session window and refresh it with a single login before each batch.

### L-UI-025  Enabling agent services and connectors needs the Administrator UI (a UI bot), overturned 2026-09-28
**Was believed:** 2026-07 to 2026-09-22 · **Overturned by:** L-UI-001, L-UI-002
A UI bot was built to enable Data Integration and connectors on an agent because no REST verb was known and the REST attempts gave router artifacts. A managed MCP tool did it on 2026-09-23 and a REST PUT on the runtime-environment selections did it on 2026-09-28, found by capturing the UI's own call.

### L-UI-026  CAI publish has to be driven through the designer UI, overturned 2026-07-25
**Was believed:** 2026-07-08 to 2026-07-24 · **Overturned by:** L-UI-001
In early July a Playwright driver published CAI processes through the designer (close the service-switcher modal, find the shell frame, click the exact Publish button, check publication status over REST first, run headed under xvfb).
